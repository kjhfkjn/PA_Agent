# 多周期上下文数据流

PA Agent 将交易数据分成两个视图：

- **主交易周期 K 线**：用户在 GUI 选择的周期，用于图表和当前分析。
- **高周期上下文特征**：高于主交易周期的结构摘要，只送入 LLM，不替换图表。

## 配置

在「通用设置 → 多周期上下文」中设置逗号分隔的上下文周期。也可以直接编辑
`config/settings.json`：

```json
{
  "context": {
    "enabled": true,
    "timeframes": ["15m", "1h"],
    "timeframes_by_primary": {
      "5m": ["15m", "1h"],
      "15m": ["1h", "4h"],
      "1h": ["4h", "1d"]
    },
    "session_timezone": "",
    "session_anchor": "",
    "session_by_symbol": {
      "MES!": {
        "timezone": "America/Chicago",
        "anchor": "17:00"
      }
    }
  }
}
```

`timeframes` 留空时按当前主周期自动选择上下文周期。
`session_timezone` 与 `session_anchor` 留空时按品种推断；CME 期货默认使用
`America/Chicago 17:00`，外汇/黄金默认使用 `America/New_York 17:00`。

## 采集与更新

1. 扩展在 TradingView 打开期间按当前活动图表捕获快照。每个快照按“品种 + 周期”
   独立保存 K 线、截止时间、来源和接收时间。
2. 可以先用 TradingView 分别加载高周期图表完成历史底稿采集，再切回主交易周期。
3. 开始交易后，当前高周期 K 线由主周期数据按交易时段锚点滚动聚合，无需再次切换
   图表周期。
4. 原生高周期快照只补足主周期覆盖范围之前的背景；当前桶始终来自主周期续接。

## 截止时间与回放

每次分析先读取主交易周期的回放截止时间，再用这个截止时间过滤全部高周期原生快照。
扩展的 `du` / `series_update` 快照更新会记录当前活动序列边缘，因此回放前进或倒退
时都会更新主截止时间，不会把其他周期在截止时间之后的数据混入特征。

## 特征契约

每条上下文特征使用统一字段：

| 字段 | 含义 |
|------|------|
| `symbol` / `timeframe` | 品种与上下文周期 |
| `as_of_ms` | 与主交易周期一致的截止时间 |
| `source` | 数据来源 |
| `method` | 聚合与特征计算方法 |
| `bars_used` | 实际参与计算的 K 线数 |
| `available` | 当前是否可用 |
| `provenance` | 交易时段、聚合方式和原生历史补足说明 |
| `data` | 特征内容及当前桶是否收盘等元数据 |

缺少足够历史或无法续接当前桶时，记录仍会传给 LLM，但明确标记为“不可用”，不会用
旧的原生高周期快照冒充当前数据。分析记录中的 `external_features` 会保存这些上下文
快照，便于回看当时 LLM 实际收到的内容。
